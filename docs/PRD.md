# Design QA — PRD

Версия: 2.0 · 16 октября 2026 · Статус: согласован локальный сценарий; заменяет PRD 1.0.

Связанные документы: [TDD.md](TDD.md), [DEVELOPMENT_PLAN.md](DEVELOPMENT_PLAN.md).

## 1. Продукт и задача

Локальный инструмент ручного сравнения двух изображений: скриншота сайта и экспорта макета из Figma. Пользователь самостоятельно получает оба файла, выбирает их в браузере, сравнивает и отмечает расхождения. Изображения и замечания обрабатываются на его компьютере.

Корпоративный сервер, доступ к стендам, VPN и собственная регистрация для этого сценария не нужны. Приложение — статическая браузерная страница, запускаемая локально. Статический web-сервер только раздаёт приложение, не принимает изображения.

## 2. Основной сценарий

1. Открыть приложение без ввода имени и настройки проекта.
2. Выбрать «Скриншот сайта» и «Макет из Figma» с компьютера; для Figma предварительно экспортировать PNG, желательно 1×.
3. Увидеть имена и реальные размеры изображений, предупреждение при разных размерах.
4. Сравнивать через наложение, разделитель или рядом; менять zoom и перемещать холст.
5. Выделить область на скриншоте сайта и добавить текст замечания.
6. Выбрать замечание в списке, увидеть область, изменить текст, отметить решённым или удалить.
7. При необходимости скачать JSON со списком замечаний. Файлы изображений в отчёт не включаются.

## 3. Что входит в текущую версию

- Два локальных файла PNG/JPEG, выбор, замена и очистка.
- Проверка формата, полного декодирования, размера файла и изображения.
- Overlay с прозрачностью, slider с разделителем, side-by-side.
- Zoom 1–400%, fit, 1:1, pan; общая геометрия режимов.
- Прямоугольные замечания в исходных пикселях скриншота сайта; текст, OPEN/RESOLVED, выбор и удаление.
- Локальный JSON-экспорт замечаний и понятное предупреждение о времени жизни сессии.
- Работа без backend, БД, cookies участника, внешних сервисов и загрузки изображений в сеть.

## 4. Что отложено

Серверный capture/worker/очередь, URL стендов, корпоративные сетевые политики, профили авторизации, API Figma и автоматический импорт, проекты/страницы/viewport как серверные сущности, общая история, участники, обсуждения, immutable revisions, перенос замечаний, diff/AI и серверное хранилище.

Нет обещания восстановления сессии после перезагрузки. IndexedDB, импорт отчёта и сохранение проекта с изображениями — отдельные будущие задачи. Экспорт замечаний не является резервной копией изображений.

## 5. Функциональные требования

### FR-01. Локальный ввод файлов

Два независимых подписанных поля: «Скриншот сайта», «Макет из Figma». После выбора показывать имя, ширину, высоту и состояние чтения. Поддерживаются статический PNG и JPEG; SVG, GIF, APNG и остальные форматы отклоняются. Проверять байтовую сигнатуру, а не только расширение/MIME.

На один файл: не более 15 MiB, ширина 1–4096 px, высота 1–10000 px, не более 25 600 000 пикселей. Лимиты проверять до полного декодирования по заголовку и повторно по декодированному изображению. Ошибочный или повреждённый файл не заменяет уже открытое изображение. При быстрых последовательных выборах действует последний выбор.

Отображать PNG alpha поверх белого фона. Изображения не масштабируются и не обрезаются при импорте; отображение меняется только zoom. JPEG показывается с той ориентацией, которую применяет браузерный декодер. Предпочтительный экспорт Figma — PNG 1×; автоматически исправлять экспорт 2× нельзя.

### FR-02. Геометрия и сравнение

Изображения выровнены левыми верхними углами. Общий холст имеет максимальные ширину и высоту пары. Разные размеры допустимы; предупреждение объясняет отсутствие автоматического выравнивания. За пределами изображения видна штриховка. Разница размеров не считается найденной ошибкой.

| Режим | Поведение |
|---|---|
| Наложение | Скриншот сайта снизу, Figma сверху; прозрачность макета 0–100%, начально 50% |
| Разделитель | Сайт слева, Figma справа; вертикальная граница 0–100%, начально 50%; drag и клавиатура |
| Рядом | Figma слева, сайт справа; общий zoom и центр в координатах изображений |

Zoom 1–400%, начальный fit после загрузки пары. «1:1» — один пиксель изображения на один CSS-пиксель. Кнопки +/−, fit и 1:1 доступны с клавиатуры. Zoom под указателем сохраняет точку под ним. При смене режима сохраняются zoom и центр; fit пересчитывается только по явному действию или новой паре.

Pan доступен отдельным инструментом и временно через Space вне текстовых полей. Escape отменяет незавершённое выделение. Переключение режима не изменяет координаты замечаний. При resize сохранять текущую геометрию; кнопка fit помогает вписать заново.

### FR-03. Замечания

Рисование доступно после загрузки обоих изображений. В режиме «Рядом» область рисуется только на правом скриншоте сайта; в остальных режимах — на координатной плоскости сайта независимо от видимого слоя.

Координаты — конечные числа исходного скриншота: x/y≥0, width/height≥1, x+width≤site.width, y+height≤site.height. Область вне скриншота сайта не принимает выделение. Прямоугольник меньше 1×1 px не создаёт замечание. Обратный drag нормализуется; выход за границу ограничивается размером сайта.

После drag открывается форма с обязательным текстом 1–5000 символов после trim. Ошибка сохраняет черновик и фокус; Escape/«Отмена» убирает только черновик. Не более 500 замечаний на пару. Текст показывается как обычный текст.

Замечание имеет id, rect, body и state OPEN/RESOLVED. Разрешены изменение текста, смена состояния и удаление. Выбор в списке подсвечивает область и центрирует просмотр. Нет автора, обсуждений и серверной истории. Исходный rect сохранённого замечания не редактируется; ошибочное замечание можно удалить и создать заново.

### FR-04. Замена и срок жизни

Одна рабочая пара на вкладку. Если есть замечания, успешная замена любого изображения, очистка или «Новая пара» требует подтверждения сброса замечаний. Отмена оставляет оба изображения и все заметки. Ошибочный новый файл ничего не сбрасывает. Подтверждённая замена начинает новую пару и очищает замечания.

Страница явно сообщает: сессия хранится в памяти вкладки, после закрытия/перезагрузки потребуется снова выбрать файлы. При наличии замечаний использовать стандартное предупреждение браузера о выходе; его показ зависит от браузера и не заменяет сообщение в UI. Никакого сохранения изображений в localStorage.

### FR-05. Экспорт

«Скачать замечания» создаёт JSON schemaVersion=1 с экспортной датой, именами/размерами обоих изображений и замечаниями (id, rect, body, state). Нет путей к файлам, blob URL или бинарных изображений. Пустой список не скачивается. Пользователь сам выбирает, кому передать файл; автоматических отправок нет. Импорт JSON не входит в текущую версию.

## 6. Нефункциональные требования

- После загрузки страницы работа с файлами и сравнение не выполняют HTTP-запросов. Нет API, аналитики, удалённых шрифтов и телеметрии. Локальные blob URLs допустимы.
- Ошибки понятны по-русски, выбранные валидные файлы сохраняются при ошибках.
- Управление доступно клавиатурой, поля имеют подписи, фокус виден. Разделитель имеет range/slider semantics.
- Интерфейс работоспособен на 375 px без горизонтального скролла страницы; холст имеет собственную область pan.
- Object URLs освобождаются при замене/очистке/размонтировании; поздно завершившийся импорт не возвращает устаревший файл.
- Не нужны Docker, пароли, env, PostgreSQL и MinIO для установки, тестов, сборки и запуска текущей версии.
- Поддержка: актуальные desktop Chromium/Firefox/Safari; автоматическая браузерная приёмка на Chromium. Touch поддерживает базовый pan/выбор файлов, сложные мультитач-жесты не обещаются.

## 7. Приёмка v2 (новая нумерация)

| Критерий | Проверяемый результат |
|---|---|
| LC-01 | Чистая установка/сборка/запуск без БД, env и Docker открывают сравнение, нет запросов /api |
| LC-02 | PNG/JPEG читаются; неверный формат/APNG/corrupt/лимиты отклоняются с сохранением прежнего файла |
| LC-03 | Сайт и Figma подписаны, размеры видны, разные размеры предупреждаются без resize |
| LC-04 | Три режима, overlay 0/50/100 и divider 0/50/100 дают заявленные слои |
| LC-05 | Fit/1:1/1–400% и pan сохраняют исходную геометрию; смена режима не сдвигает rect |
| LC-06 | Прямоугольник нормализуется и ограничивается сайтом, в side-by-side рисуется только справа |
| LC-07 | Текст/state/удаление/выбор работают; текст не интерпретируется как HTML; лимиты соблюдены |
| LC-08 | Замена/очистка с замечаниями подтверждается; отмена и плохой файл сохраняют состояние |
| LC-09 | JSON содержит правильные имена, размеры и координаты; нет бинарных изображений/blob URL |
| LC-10 | После загрузки страницы сравнение/заметки не отправляют сетевых запросов и не используют backend |
| LC-11 | Быстрый повторный выбор оставляет последний файл, ненужные URL освобождаются |
| LC-12 | Клавиатура, видимый фокус, сообщения об ошибках и 375px проверены в браузере |

Критерии AC-01–AC-19 версии1 относятся к отложенной серверной концепции и не используются для приёмки v2. Старый этап A остаётся в Git и журнале как история, а не как требование текущего продукта.
